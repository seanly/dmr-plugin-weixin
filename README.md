# dmr-plugin-weixin

External [DMR](https://github.com/seanly/dmr) plugin (HashiCorp **go-plugin** + `net/rpc`) that connects **Weixin over an ilink/bot HTTP gateway** to the DMR agent: long-poll `getupdates` → `RunAgent` → `sendmessage` (with **`context_token`**). Supports **multiple bots** (`bots[]`, similar in spirit to DMR’s Feishu integration). Implements **`ProvideApprover`** for `weixin:*:p2p:*` tapes (y/s/a/n, same idea as Feishu).

**Feishu vs Weixin in DMR:** Feishu ships **in-tree** as a built-in plugin (`plugins/feishu` in the **dmr** repo, wired into the main `dmr` binary via `plugin.RegisterBuiltin`). **Weixin** (**this repo**) stays **out-of-tree**: you compile `dmr-plugin-weixin` and register it with **`path`** in **`config.toml`**. Same broad UX (tape names, cron + `tape_name`, dedup, `allow_from`, send tools, approver), different protocols — Feishu Open Platform WebSocket/events vs ilink HTTP + `context_token`.

### Design (reference TS → Go → DMR agent)

This is exactly the split you described:

1. **Reference implementation** — [@tencent-weixin/openclaw-weixin](https://www.npmjs.com/package/@tencent-weixin/openclaw-weixin) TypeScript is used **only as a spec**: HTTP paths (`ilink/bot/*`), headers (`AuthorizationType`, per-request `X-WECHAT-UIN`, optional `SKRouteTag`), `base_info`, `get_updates_buf`, `context_token` on sends, and outbound `sendmessage` shapes incl. CDN (`getuploadurl`). The npm package is **not** linked or executed by DMR.

2. **Go implementation** — `gateway_client.go`, `types.go`, `monitor.go`, `reply.go`, … as a **standalone binary** suitable for `go-plugin`.

3. **DMR AI agent integration** — **External** HashiCorp **go-plugin** pattern (`SetHostClient` + host RPC): analogous *role* to DMR’s **built-in** Feishu plugin (tapes, queue, dedup / `allow_from`, send tools, approver). Per-chat tapes here are **`weixin:p2p:<peer>`** or **`weixin:<bot_id>:p2p:<peer>`** — see **Tape names**. OpenClaw-specific pieces (plugin-sdk routing, slash commands, pairing files) are **not** copied.

#### Sending files vs text

Use **`weixinSendFile`** with a **local path** or **http(s) URL**; set **`file_type`** and/or **`media_type`** (`auto`, `image`, `video`, `file`, or ilink CDN-style **`1`–`4`**; **`voice`/`4` not supported outbound**). If both are set they must agree. Pipeline uses **`getuploadurl`** and CDN upload — set **`cdn_base_url`** (QR **`dmr-weixin-login`** can write defaults).

**You only need DMR to run it** — add a **`[[plugins]]`** stanza with **`name = "weixin"`**, then put the keys below **`[plugins.config]`** **immediately under** that stanza (see **DMR configuration**). **`gateway_base_url`** and **`token`** are required. **`cdn_base_url`** can be omitted for **text-only**; configure it for **`weixinSendFile`** uploads.

## Requirements

- Go **1.25+** (matches DMR)
- `go.work` from **`go.work.example`** (sibling `../dmr` checkout) for local iteration with unreleased **dmr**, or **`make bump-dmr`** so **`go.mod`** pins **`github.com/seanly/dmr`** at **`$(DMR_DIR)` HEAD** (set **`GOPRIVATE=github.com/seanly/dmr`** when the module is private)
- A running **ilink/bot-compatible** gateway and **bot token**. Set **`cdn_base_url`** when using **`weixinSendFile`** (Tencent-style **`https://novac2c.cdn.weixin.qq.com/c2c`** is typical); text-only **`weixinSendText`** runs without CDN if omitted.
- **Not** the WeChat Official Account Open Platform API — this is the personal-channel style `ilink/bot` stack

### Compliance note

Personal Weixin automation may conflict with Tencent’s terms or risk controls. Deploy only if you accept that risk; this README is not legal advice.

## What you put in DMR config (no defaults for URL/token)

These are **not** generated by DMR and have **no universal default**. They must match **your gateway deployment**:

| Key | Meaning |
|-----|--------|
| `gateway_base_url` | Root URL of the HTTP API; the plugin appends paths such as `ilink/bot/getupdates`, `ilink/bot/sendmessage`. Trailing `/` optional. |
| `cdn_base_url` | CDN root for **`getuploadurl`/upload pipeline** (**`weixinSendFile`**). Use Tencent-style **`https://novac2c.cdn.weixin.qq.com/c2c`** unless your gateway specifies otherwise; **`dmr-weixin-login`** can write defaults. Omit if you never send attachments. |
| `token` | Secret the gateway expects on `Authorization: Bearer <token>`. Put **only the token** in **`config.toml`** (do **not** include the word `Bearer`). |

#### Multiple bots (`bots`)

To run **more than one** Weixin gateway identity under the **same** plugin binary, declare **`[[bots]]`** under **`[plugins.config]`**. Each bot row accepts the **same keys** as the legacy flat config: **`gateway_base_url`**, **`cdn_base_url`**, **`token`**, **`credentials_path`**, **`account_id`**, **`allow_from`**, **`sk_route_tag`**, **`channel_version`**.

- When **`bots` has two or more entries**, **`id`** is **required** on **every** row: it must be **unique**, safe for filenames (validated like **`dmr-weixin-login`** **`--id`**), appears in tapes as **`weixin:<id>:p2p:<peer>`**, and is the value you pass as **`weixin_bot`** when using **`peer_id`** without a **`tape_name`** (see **Tools**).
- When **`bots`** is omitted, legacy **top-level** keys are folded into a **single** implicit bot (backward compatible).

If there is **exactly one** bot **and** it has **no** `id`, tapes stay **`weixin:p2p:<peer>`**. If there are **multiple** bots **or** the sole bot sets **`id`**, tapes use **`weixin:<id>:p2p:<peer>`** so approvals, dedupe, cron bindings, and off-session **`tape_name`** stay isolated per gateway identity.

Root-level **`gateway_base_url`** / **`token`** / **`cdn_base_url`** / … are **mirrored from `bots[0]`** after config finalize so older dashboards that read only legacy fields keep working.

**CLI login (optional)** — **`dmr-weixin-login`** writes `gateway_base_url`, `cdn_base_url`, `token`, and **`account_id`** JSON per login (use **`--id`** for separate credential files — see **Login once** below). Reference each bot’s file with **`credentials_path`** on that bot row (paths resolve relative to the **`config.toml`** directory like **`extra_prompt_file`**). Non-empty fields from the credentials file overlay the same bot’s TOML keys; **`account_id`** in JSON isolates **`get_updates_buf`** for that identity.

You can still set URL/token/account **only** in **`config.toml`** when you prefer not to use JSON overlays.

The printed **liteapp** URL (`liteapp.weixin.qq.com/...`) often shows only a “open in WeChat” hint in desktop browsers — **no visible QR**. `dmr-weixin-login` also draws the **same URL as a QR in the terminal** (Unicode blocks); scan that with WeChat. Use `-no-terminal-qr` if you only want the link. A small local **web** UI would be the same idea (render a QR for that URL); not shipped here.

How you obtain the three strings without the helper is **outside DMR**: gateway operator docs, `docker-compose`/Helm, or another tool that stored `baseUrl` / `cdnBaseUrl` / `token` for the same protocol.

| Key | Default in plugin |
|-----|-------------------|
| `account_id` | If omitted or empty, the plugin uses **`default`**. Use different values only if you run **multiple** bot identities and need separate `get_updates_buf` files. |

## Layout / build

Sources follow the same layout as **`dmr-plugin-jenkins`**: plugin core in **`internal/weixin`**, binaries under **`cmd/`**, policies in **`policies/`**.

```bash
make build         # go mod tidy + compile to bin/dmr-plugin-weixin
make login-build   # compile to bin/dmr-weixin-login
make test          # go test ./...
make install       # copies bin/* to ~/.dmr/plugins/
make install-policy  # copies policies/weixin.rego to ~/.dmr/etc/policies/ (recommended perms for OPA reload)
make install-all     # install + install-policy
make bump-dmr      # pin github.com/seanly/dmr to ../dmr HEAD (override DMR_DIR=...)
```

**Login once** (writes `~/.dmr/var/lib/weixin/credentials.json` by default; **`--id <label>`** uses `~/.dmr/var/lib/weixin/<label>/credentials.json` and adds **`account_id`** to the JSON; override destination with **`-out`**):

```bash
./bin/dmr-weixin-login
# second account example:
# ./bin/dmr-weixin-login -- -id work

# or: go run ./cmd/dmr-weixin-login -- -wait 15m
```

`--id` must match `[a-zA-Z0-9][a-zA-Z0-9._-]{0,63}` (safe path segment).

## DMR configuration (`config.toml`; default **`~/.dmr/config.toml`**)

DMR loads **TOML** only ([`config.example.toml`](https://github.com/seanly/dmr/blob/main/config.example.toml)); YAML configs are rejected.

Put **`[plugins.config]`** directly **below** the **`[[plugins]]` block it belongs to** (before any following **`[[plugins]]`**). Use **`cli_approver`** only if needed; disable it (`enabled = false`) when this plugin is your sole **`ProvideApprover`**.

```toml
[[plugins]]
name = "opa_policy"
enabled = true

[[plugins]]
name = "cli_approver"
enabled = false

[[plugins]]
name = "weixin"
enabled = true
path = "~/.dmr/plugins/dmr-plugin-weixin"

[plugins.config]
# Option A: paste secrets from your gateway (uncomment):
# gateway_base_url = "https://api.example.com/"
# cdn_base_url = "https://cdn.example.com"
# token = "your-bot-token"

# Option B: after ./dmr-weixin-login — JSON file overlays gateway/cdn/token and optional account_id (from ./dmr-weixin-login --id ...)
# Paths are relative to the directory containing config.toml; V2 convention is under ~/.dmr/
credentials_path = "var/lib/weixin/credentials.json"  # multi-login: "var/lib/weixin/work/credentials.json"

# account_id = "default"   # optional; default plugin value is default; credentials JSON can override when present

allow_from = []            # optional allowlist entries, e.g. ["wxid_xxx@im.wechat"]

approval_timeout_sec = 300
dedup_ttl_minutes = 10

# optional: extra_prompt, extra_prompt_file — same idea as DMR built-in Feishu
# sk_route_tag = ""

# optional: same as built-in Feishu — requires allow_from
# dmr_restart_trigger / dmr_restart_token

# Multi-bot (two or more ilink identities in one plugin):
#bots = [
#  { id = "home", credentials_path = "var/lib/weixin/home/credentials.json" },
#  { id = "work", credentials_path = "var/lib/weixin/work/credentials.json" },
#]
# Each `{ }` row supports the same keys as legacy single-bot: gateway_base_url,
# token, cdn_base_url, allow_from, sk_route_tag, channel_version, account_id, etc.

```

After merge, **`gateway_base_url`** and **`token`** must be non-empty (`Init` fails otherwise). Omit **`cdn_base_url`** only if you do not send files via **`weixinSendFile`** (uploads fail without CDN base).

`X-WECHAT-UIN` is generated **per HTTP request** by the plugin; you do not configure it.

Sync cursor **`get_updates_buf`** is stored per bot (**`account_id`**) under **`config_base_dir/.dmr-weixin/`** (DMR sets **`config_base_dir`** from the directory of your **`config.toml`**). If that is missing, the OS user cache dir is used. Use distinct **`account_id`** (often from **`dmr-weixin-login`**) across identities so polling cursors never collide.

## Tape names

Inbound private chat tapes:

- **`weixin:p2p:<from_user_id>`** when **exactly one** bot is configured **and** that bot has **no** `id` (`xxx@im.wechat` peer form).
- **`weixin:<bot_id>:p2p:<from_user_id>`** when **`bots`** has **multiple** entries **or** the sole bot sets **`id`**.

One global inbound queue worker processes jobs in order (same pattern as Feishu); routing to the correct gateway identity uses the tape prefix.

## Tools

- **`weixinSendText`** — Plain text to current peer when run from inbound context (**`tape_name`** / **`peer_id`** forbidden). For **cron-fired** runs (no inbound context), supply **`tape_name`** *or* **`peer_id`**; **`tape_name`** may be **`weixin:p2p:<peer>`** or **`weixin:<bot_id>:p2p:<peer>`** when several bots apply. With **`peer_id`** and **multiple bots**, **`weixin_bot`** must be the **`id`** string from **`bots`**. Requires a cached **`context_token`**. Set **`DMR_WEIXIN_DEBUG_SEND=1`** on `dmr serve` to log truncated `sendmessage` bodies when debugging.
- **`weixinSendFile`** — Send an attachment (picture, video, or generic file) via CDN upload + `sendmessage`; `file_path` may be local or **http(s)** URL. Same off-session **`tape_name`**, **`peer_id`**, **`weixin_bot`** rules as **`weixinSendText`**. Optional **`text`** caption. Use **`file_type`** and/or **`media_type`** (`auto`, `image`, `video`, `file`; or CDN-style **`1`–`4`** matching ilink **`media_type`**, **`4`/`voice` not supported outbound** — both fields must agree if both are set).

## Approvals

**`ProvideApprover`** tapes: **`weixin:p2p:*`** and **`weixin:*:p2p:*`** (scoped prefix when **`id`** / multi-bot). Plain-text prompts. Replies: **y / s / a / n** (single), or batch **yes / 1,3,5** style, aligned with CLI approver semantics.

## Cron

Add jobs **in this Weixin chat** so `cronAdd` binds the current session tape (`weixin:p2p:<peer_id>` **or** `weixin:<bot_id>:p2p:<peer_id>` matching your config); `cronAdd` does not accept a separate **`tape_name`**. When the job runs, deliver with **`weixinSendText`** (or **`weixinSendFile`** for attachments) using **`tape_name`** or **`peer_id`** (scheduled runs have no inbound context) — mirror how Feishu uses **`tape_name`** with **`feishuSendText`**.
